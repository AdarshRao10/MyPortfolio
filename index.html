How I got here

It started in 2019, with buttons. Here's the short version, one job at a time.

2019

Robosoft Technologies, India. Junior Software Developer, June 2019 to March 2021.

I started with the parts people can touch.

My first job was building web pages: forms, layouts, the screens people actually click on. I delivered five client apps that had to pass accessibility audits for US users, which taught me early that "it works on my machine" isn't the bar.

But the thing that pulled me in was a set of Python scripts. They replaced 12 manual data entry jobs and gave the operations team about 25 hours back every month. Nobody sees a script like that, and I liked that.

  • 5 client-facing apps built with JavaScript, jQuery and Bootstrap
  • Figma designs turned into Angular components on 4 projects
  • 10M+ customer records managed in SQL Server, with PL/SQL procedures
  • 150+ unit tests that caught 12 critical flaws before QA

2021

Capgemini, India. Software Engineer, April 2021 to May 2023.

I became the person you call when it's slow.

At Capgemini I moved to Java. Spring Boot services with Kafka in the middle, and real money moving through them: over $2.2M in transactions a month. Speed and uptime stopped being abstract very quickly.

I spent a lot of time in Dynatrace and logs, tracking down production bottlenecks. Add up all the fixes and that's 200+ hours of downtime that never happened. Nobody writes a thank-you note for an outage that didn't happen, and that's fine.

  • 65+ high-priority production bottlenecks diagnosed
  • 25+ REST endpoints on Oracle, with query latency cut by 300ms through indexing
  • 3 zero-downtime releases a month on Azure Kubernetes Service

2023

Dell Technologies, India. Software Engineer, May 2023 to January 2024.

I made the paperwork run itself.

At Dell the problem was ownership: who owns which artifact, across 12 enterprise applications, and can you prove it? I built the Spring Boot services behind that, with Kafka sending ownership updates automatically so people didn't have to do it by hand.

That removed 12 manual steps from every release, and support tickets dropped by 45 a month. I also got deployments down from three days to 18 hours.

  • 4,000+ verifiable audit logs generated
  • JWT and Spring Security across 5 governance platforms on Azure
  • Portal load time cut by 2.5 seconds for 30,000 monthly users
  • 10+ internal dashboards standardized in TypeScript

2024

University of Texas at Arlington. MS in Computer & Information Sciences, January 2024 to December 2025.

A new city, and a new kind of problem.

In January 2024 I moved to Arlington, Texas for my master's degree. Along the way I built two LLM projects of my own.

The first is a layer that checks whether an LLM is making things up, using retrieval, vector similarity scores and confidence filtering. It cut wrong answers by 35%. The second is a multi-agent system that handles workflows like ticket resolution, and it cut manual processing time by 60%. You can read more about both further down.

  • RAG pipelines with Pinecone
  • LangGraph agents talking over Kafka

2025

BotStacks, USA. Software Engineer, May 2025 to August 2025.

My first job building AI, with the backend I already knew.

At BotStacks I built the backend for a customer-facing chatbot: Node.js, LangGraph and OpenAI behind a React interface. The interesting problem turned out to be familiar backend stuff. Caching, retries, throttling, and making sure a conversation doesn't get dropped halfway.

Adding Redis for context retrieval made LLM queries about 30% faster in early testing.

  • Session-aware routing for multi-turn conversations, built with LangGraph
  • Secure API gateways for OpenAI traffic on AWS ECS, with throttling and retry logic
  • First CI/CD pipelines with Docker and GitHub Actions

2026

Uber, USA. Software Developer, June 2026 to present.

Now: backend at Uber, with LLMs on top.

Today I write Java 17 and Spring Boot at Uber, and I'm building the backend for an internal tool that uses an LLM to read documents. The first rollout covered 12,000+ documents, and it's projected to save 11 days of review time every quarter.

I'm also helping with a Kubernetes migration, and with release pipelines that have security scans and rollbacks built in.

  • Java 17, Spring Boot, DocStore and PostgreSQL
  • Bazel and Up CD pipelines that cut release cycles by 3.5 hours
  • Helm-based Kubernetes migration across 2 engineering units

That's the story so far.

The network is full for now, but I'd like to keep adding to it. If you have something worth building, I'd love to hear about it.
